# Telegram ↔ Usedesk: мост только для группы

Сервис передаёт сообщения между одной разрешённой Telegram-группой и одним чатом Usedesk.

- Личные сообщения боту игнорируются и не попадают в Usedesk.
- Сообщения из посторонних групп игнорируются.
- Ответ агента в Usedesk отправляется обратно в разрешённую Telegram-группу.
- Текст, подписи, геолокация и контакты передаются напрямую.
- Фото и другие файлы из Telegram передаются в Usedesk защищённой временной ссылкой.
- Связь с чатом Usedesk хранится в PostgreSQL и не теряется после деплоя.

## Что подготовить

1. Telegram-бот, созданный через `@BotFather`.
2. В BotFather включено `Allow Groups`, а `Group Privacy` выключен.
3. Бот добавлен администратором в нужную группу.
4. В Usedesk включено расширение `Usedesk API`.
5. Репозиторий GitHub/GitLab/Bitbucket для подключения к Render.

Не подключайте токен этого бота напрямую к Telegram-каналу Usedesk: у Telegram-бота может быть только один активный webhook.

## 1. Создать чатовый канал Usedesk

1. Откройте `Каналы → Добавить канал`.
2. Выберите `Чат`.
3. Назовите его `Telegram Group Bridge` и сохраните.

Нужен ID этого чатового канала. После создания API-канала из следующего шага его можно получить командой:

```bash
USEDESK_API_TOKEN="ваш_секретный_ключ" npm run list:channels
```

Число напротив `Telegram Group Bridge` — это `USEDESK_CHAT_CHANNEL_ID`.

## 2. Создать API-канал Usedesk

1. Откройте `Каналы → Добавить канал → API`.
2. Назовите канал `Telegram Bridge API`.
3. Поле `Redirect URL` пока оставьте пустым.
4. Включите `JSON запрос` и `Отправлять в UTF-8`.
5. В `Следить за каналами` выберите только `Telegram Group Bridge`.
6. В блоке `Отслеживание чатов` включите:
   - новый чат;
   - все сообщения чата;
   - возобновление чата.
7. Сохраните канал.

После сохранения появятся:

- `ID приложения` → `USEDESK_APP_ID`;
- `Секретный ключ` → `USEDESK_API_TOKEN`.

В разных версиях Usedesk поле `secret` в webhook может содержать ID приложения или секретный ключ. Сервис безопасно принимает оба значения только для настроенного API-канала.

ID компании находится в `Настройки → Компания` → `USEDESK_COMPANY_ID`.

## 3. Узнать ID Telegram-группы

Пока Telegram webhook ещё не подключён:

1. Отправьте новое обычное сообщение в нужной группе.
2. Запустите:

```bash
TELEGRAM_BOT_TOKEN="токен_бота" npm run detect:group
```

Команда покажет название группы и отрицательное число вида `-1001234567890`. Это `TELEGRAM_GROUP_ID`.

## 4. Переменные Render

Blueprint запросит следующие значения:

| Переменная | Значение |
|---|---|
| `TELEGRAM_BOT_TOKEN` | Токен от BotFather |
| `TELEGRAM_GROUP_ID` | ID нужной группы с минусом |
| `WEBHOOK_SECRET` | Любая случайная строка из 32+ латинских букв и цифр |
| `USEDESK_API_TOKEN` | Секретный ключ API-канала |
| `USEDESK_COMPANY_ID` | ID компании |
| `USEDESK_CHAT_CHANNEL_ID` | ID чатового канала `Telegram Group Bridge` |
| `USEDESK_APP_ID` | ID приложения API-канала |

`DATABASE_URL` подключается к Managed PostgreSQL автоматически. Публичный адрес сервис получает от Render автоматически.

## 5. Подключить webhook Usedesk

После успешного деплоя откройте настройки `Telegram Bridge API` и укажите:

```text
https://ИМЯ-СЕРВИСА.onrender.com/webhooks/usedesk/WEBHOOK_SECRET
```

Замените адрес и `WEBHOOK_SECRET` на реальные значения. Usedesk отправит проверочный `ping`; сервис ответит кодом 200. Сохраните канал.

## 6. Проверка

1. Отправьте сообщение в разрешённой Telegram-группе.
2. В Usedesk должен появиться чат `Telegram: название группы`.
3. Ответьте публичным сообщением из Usedesk.
4. Ответ должен появиться в Telegram-группе от имени бота.
5. Напишите боту лично — в Usedesk ничего появиться не должно.

## Локальная проверка

```bash
npm install
cp .env.example .env
# заполните .env
node --env-file=.env src/server.js
```

Тесты:

```bash
npm test
```
